# Доказательства выполнения: CLI, браузер, нативные окна

Справочник по скриншотам и функциональным проверкам. Читай перед съёмкой
доказательств и при выборе инструмента.

## Правило

Раздел «Результат выполнения» показывает результат, а не процесс его
получения. Что в нём будет, решает методичка:

- методичка просит скриншоты — настоящий снимок окна (`shot.ps1`) или
  страницы (`capture_cdp.js`);
- методичка просит «результат работы программы» — фактический вывод, таблица
  расчётов или сам созданный файл;
- методичка молчит — только результат, без картинки.

PNG обязателен лишь там, где его просят. Отрисованный из текста кадр
«терминала» доказательством не является: его создаёт тот же агент, что и
работу, поэтому он ничего не подтверждает, а выглядит как имитация ручной
работы. Не подменяй результат вымышленным логом и не рисуй окно, которого не
было.

- CLI — вывод приводится текстом в `code` или снимается с реального окна
  через `shot.ps1`; отрисованного «терминала» в инструментах больше нет.
- Веб-страница — CDP (`capture_cdp.js` для статики, `cdp.js` для интерактива,
  диалогов и popup).
- Нативное окно (Postman, терминал, IDE, просмотрщик) — `shot.ps1` либо
  глобальный скилл `screenshot`, если нужен OCR или активное окно пользователя.
- Падение UI-теста — fixture Selenium/Appium, а не скриншот рабочего стола.

После съёмки `check-screenshot` проверяет сигнатуру PNG, минимальный размер
640×360 и то, что кадр не одноцветный. Он не открывает изображение, не создаёт
окон и не меняет фокус.

## CLI: вывод команды

Скриншот консоли не рисуется. Отрисовка вывода «под окно терминала» удалена
из инструментов: такой кадр ничего не доказывает и читается как постановка.

Порядок:

1. Выполни команду и сохрани её фактический вывод.
2. Покажи результат так, как просит методичка:
   - текстом — элементом `code` в `content.json`;
   - настоящим снимком окна — `shot.ps1` по живому окну консоли, где видно
     приглашение с рабочим каталогом и сам запуск.

Воспроизводимую команду всё равно фиксируй в состоянии: она нужна, чтобы
преподаватель мог повторить запуск.

```json
"commands": {
  "cli_evidence": "py app.py"
}
```

Длинный вывод в отчёт целиком не переносится: в текст идёт значимая часть или
таблица с результатом, полный вывод — в файл рядом с отчётом.

## Браузер: `cdp.js`

Node ≥ 22, внешних зависимостей нет. Edge/Chrome запускается сам с
`--remote-debugging-port`; профиль — в `%TEMP%\edge-cdp-profile`. `launch`
только стартует браузер, `run` подключается и выполняет действия в порядке
аргументов — почти всегда нужна пара команд.

1. **Статика** — headless, быстро и детерминированно:

   ```text
   node <папка скилла>\scripts\capture_cdp.js --file lab\ex1.html --out lab\screenshots\ex1.png
   ```

   Либо двухшаговый вариант:

   ```text
   node <папка скилла>\scripts\cdp.js launch --headless
   node <папка скилла>\scripts\cdp.js run --file lab\ex1.html --wait 300 --shot lab\screenshots\ex1.png
   ```

   `--file` предпочтительнее ручного `file:///` URL: харнес сам корректно
   экранирует пробелы и кириллицу в пути.

2. **Интерактив** (JS-эффект, состояние после действий):

   ```text
   node <папка скилла>\scripts\cdp.js run --url <URL> --eval "document.body.style.backgroundColor='red'" --shot out.png
   ```

   Результат `--eval` печатается — используй его и как функциональную
   проверку. Анимации: `--nowait-eval "..." --wait 1500 --shot out.png`.

3. **Диалоги** (alert/confirm/prompt) — только обычное окно, не headless:
   диалоги живут лишь в реальном окне, и Edge закрывает их, как только
   отключается последний DevTools-клиент. Поэтому снимок — `--os-shot`
   (вызов `shot.ps1` поверх окна Edge) при живом CDP-соединении, а обработка —
   `--dialog-action accept[:текст]|dismiss` прямо в очереди:

   ```text
   node <папка скилла>\scripts\cdp.js run --url <URL> --nowait-eval "prompt('password?')" --os-shot s1.png --dialog-action accept:answer --shot s2.png
   ```

4. **Popup / новое окно** — открывай только доверенным щелчком
   `--click "селектор"` (Input.dispatchMouseEvent даёт user activation, и
   popup-блокиратор молчит; программный `.click()` — нет), затем
   `--match <подстрока заголовка>` + `--shot`.

Грабли:

- **Кириллица в командах искажается** при передаче через CDP: в `--eval`,
  текстах диалогов и `--dialog-action` держи ASCII, кириллицу собирай в JS из
  юникода — `'\u0437\u0434\u0440\u0430\u0432\u0441\u0442\u0432\u0443\u0439'`.
- CSS-позиции обязаны иметь единицы: `style.top = '100px'`, а не `'100'`.
- Прогон завис или поплыли снимки: `node <папка скилла>\scripts\cdp.js reset` —
  закрывает доступный CDP-браузер и до трёх раз удаляет профиль. Для
  изолированного профиля передавай тот же `--profile-dir`, что и в `launch`.
- Всё складывай в `ЛРN/screenshots/`, имена — по смыслу состояния
  (`index.png`, `dialog_prompt.png`, `after_click.png`).

## Нативные окна: `shot.ps1`

```text
powershell -File <папка скилла>\scripts\shot.ps1 -Out out.png -Title "подстрока"
```

Параметры: `-Process msedge`, `-Title`, `-X/-Y/-W/-H` для региона, `-Active`,
`-Client`, `-Delay`. Для отчётного снимка не используй `-Active`, если окно не
проверено вручную: активным может оказаться редактор. Разверни окно перед
съёмкой и верни фокус пользователю после; явно сообщи об этом.

## Несколько доказательств в одном отчёте

Для per_task-ЛР каждый раздел «Результат выполнения» содержит свой `img`.
`quality-gate` требует, чтобы число рисунков в DOCX совпадало с числом `img`
в `content.json`; пропущенный скриншот блокирует сборку. Один и тот же PNG
можно вставлять в несколько разделов, но лучше снимать каждый этап отдельно.
